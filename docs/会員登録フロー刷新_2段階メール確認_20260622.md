# 会員登録フロー刷新：メール確認付き2段階登録 + 詳細プロフィール

対応日：2026-06-22

## 概要

旧来の「メール＋パスワードで即時登録」を、既存サイト（retouch-members.com）に倣った
**2段階・メール確認付き** の会員登録フローに刷新しました。

1. **Step1（仮登録）** `/signup`：メール＋パスワード＋確認を入力 → 「仮会員登録完了」モーダル表示＋確認メール送信。
2. **メール**：件名「【Retouch（リタッチ）】メール登録完了」。24時間有効の確認リンク `…/signup/account?token=…` を記載。
3. **Step2（本登録）** `/signup/account?token=…`：ユーザーネーム・氏名・カナ・電話・住所・性別・生年月日・メルマガ・お知らせ通知を入力 → 完了。
4. **完了後**：メール＋パスワードのみでログイン可能（本登録完了までログイン不可）。
5. ヘッダー「新規会員登録」ボタンを `/signup` へ変更（旧 `/guide`）。

入力項目は `customers` テーブルに保存し、マイページの「登録情報の変更」でも表示・編集できます。

## ★必須の作業（これを行わないと動作しません）

### 1. DBマイグレーションの適用（本番Supabase）★未適用だと「仮登録の処理に失敗しました」になります

次のいずれかを **Supabase SQL Editor** で実行してください（どちらも冪等・再実行可）。
- 単体: `supabase/migrations/20260622_registration_flow.sql`
- まとめて: `supabase/apply_all.sql`（正本セットアップ。末尾に同内容を統合済み）

> 「仮登録の処理に失敗しました」は、このマイグレーション未適用で `customers.registration_completed`
> カラムや `registration_tokens` テーブルが存在しないことが原因です。適用すれば解消します。

内容：
- `customers` に詳細プロフィール用カラムを追加（`username` / `last_name` / `first_name` /
  `last_name_kana` / `first_name_kana` / `prefecture` / `address_city` / `address_town` /
  `address_building` / `announcement_opt_out` / `registration_completed`）。すべて nullable または
  default 付きで、**既存行は無影響**（`registration_completed` は default true ＝既存会員は完了扱い）。
- `registration_tokens`（メール確認トークン）テーブルを新設（RLS 有効・サービスロールのみ）。

適用後、サービスロールの `select` でカラム／テーブルの追加を確認してください。

### 2. Supabase Auth「Confirm email」を有効化

本登録が完了するまでログインさせない仕組みは、未確認ユーザーをログイン不可にする
Supabase の **Authentication → Providers → Email →「Confirm email」を ON** が前提です。
（多層防御として、アプリ側でも `registration_completed=false` のユーザーはログイン後に
即サインアウトする分岐を入れていますが、設定ONを推奨します。）

### 3. 本番（Vercel）へ再デプロイ ★これをしないと旧フローのまま

`NEXT_PUBLIC_SITE_URL` が本番URLになっていること（確認メールのリンク生成に使用）。

> 【症状の説明】本番が未デプロイだと**旧1段階フロー**のままで、
> 「ご入会ありがとうございます（ログインURL `…/login`）」のウェルカムメールが即送信され、
> 情報入力ページを経由しません。デプロイ後は、サインアップ後のメールが
> **アカウント作成ページ `…/signup/account?token=…`（全情報入力）** へのリンクになり、
> 入力完了後にメール＋パスワードでログインできます（要件どおり）。

### 4. メールを「迷惑メール」ではなく「受信トレイ」に届ける（送信元ドメイン）

現状は差出人が個人 Gmail（`unaniiyashiwo@gmail.com`）のため、ブランドのドメインと
差出人ドメインが一致せず Gmail 等で Spam 判定されやすい状態です。

**対策（最も効果的）：自社ドメイン `retouch-members.com` の認証済みメールボックスから送信する。**
既存の `info@retouch-members.com` は Xserver（`sv####.xserver.jp`）で運用され SPF/DKIM 設定済みです。
`.env.local`（およびVercel）の SMTP 設定を次のように変更してください（`.env.local.example` に記載）：

```
SMTP_HOST=svXXXX.xserver.jp
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=info@retouch-members.com
SMTP_PASS=（メールボックスのパスワード）
MAIL_FROM=info@retouch-members.com          # 差出人は SMTP_USER と同一ドメインに揃える
MAIL_FROM_NAME=Retouchメンバーズ事務局
```

※ `MAIL_FROM` だけを `info@retouch-members.com` に変えて送信は Gmail のままにすると、
DKIM/DMARC が不一致になり**かえって Spam が悪化**します。必ず SMTP も同ドメインに揃えてください。
※ 可能なら `retouch-members.com` の DNS に DMARC レコードの追加も推奨します。

## データ整合（重要な設計）

- 新カラム（姓名・住所の分割）を正本とし、**既存カラムを常に自動同期**します：
  - `full_name = last_name + ' ' + first_name`
  - `full_name_kana = last_name_kana + ' ' + first_name_kana`
  - `address1 = prefecture + address_city + address_town`、`address2 = address_building`
- これにより、マイページ・管理画面・各種メール（full_name 参照）は**一切変更不要で従来どおり**動作します。
- 既存会員がプロフィール編集を開くと、分割項目が空のときは既存の `full_name` / `address1` /
  `address2` をシードするため、**保存してもデータが失われません**。
- メルマガ可否は既存の `newsletter_opt_out` を流用。お知らせ通知は新設 `announcement_opt_out`。
