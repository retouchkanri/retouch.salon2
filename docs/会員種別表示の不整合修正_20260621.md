# 会員種別の表示不整合（会員側＝メンバーズ／管理側＝アテンダー）修正メモ — 2026/06/21

## ご報告いただいた症状
対象会員：yoshi910019@ezweb.ne.jp 様

- **会員側マイページ**：「会員種別：メンバーズ会員」「お支払い：正常」と表示
- **管理側（顧客一覧・顧客詳細）**：「アテンダー会員（有効）」、メンバーズ会員は「停止」
- → 会員側と管理側で会員種別の表示が食い違っていた。

## 実際のデータ（本番DBで確認・正しい状態）
- アテンダー会員（プランコード A・月額¥0）… **有効**
- メンバーズ会員（プランコード A・月額¥1,800）… **停止（解約済）**

データ自体は正しく、**「アテンダー会員が有効」が正**です。会員側マイページの会員種別ラベルだけが誤って「メンバーズ会員」と出ていました。

## 原因
アテンダー会員は、DBのenum改修を避けるため**既存の基本会員コード「A」を流用**して作成しています（プラン名のみ「アテンダー会員」）。

会員種別の表示方法が、管理側と会員側で異なっていました。

| 画面 | 表示ロジック | yoshi様の表示 |
|---|---|---|
| 管理（顧客一覧・詳細） | 実プラン名 `primary_plan_name` を優先 | アテンダー会員 ✅ 正しい |
| 会員マイページ | コード→ラベル変換 `memberClassLabel(member_class_code)` のみ | `memberClassLabel("A")` ＝ メンバーズ会員 ❌ 誤り |

コード「A」は本来「メンバーズ会員」を指すため、コードだけで判定するとアテンダー会員（コードA流用）が「メンバーズ会員」と誤表示されていました。

## 修正内容
`src/app/mypage/page.tsx` の会員種別ラベル算出を、**管理側と同じく実プラン名 `primary_plan_name` を優先**するよう変更しました。

```
// 変更前： memberClassLabel(member_class_code) のみ
// 変更後： primary_plan_name ?? memberClassLabel(member_class_code) ?? …
```

これによりアテンダー会員はマイページでも正しく「アテンダー会員」と表示され、会員側・管理側の表示が一致します。

## 回帰がないことの確認
本番DBの有効プラン名はすべて従来ラベルと一致しているため、通常会員の表示は変わりません。

| コード | 有効プラン名 | 従来ラベル | 一致 |
|---|---|---|---|
| A | メンバーズ会員 | メンバーズ会員 | ○ |
| B | サポーター会員 | サポーター会員 | ○ |
| C | リェリーフ会員 | リェリーフ会員 | ○ |
| OWNER | オーナーズ会員 | オーナーズ会員 | ○ |
| SUPPORT | （実プラン名なし→従来通り）ヘルパーズ会員 | ヘルパーズ会員 | ○ |
| A（流用） | **アテンダー会員** | （誤）メンバーズ会員 → **正：アテンダー会員** | 修正対象 |

- ヘルパーズ会員（コードSUPPORT）は `primary_plan_name` が無いため従来どおりラベル変換にフォールバックします。
- お支払い状況・月額合計・支援数などその他の表示には変更ありません。

## 備考
- 変更ファイルは `src/app/mypage/page.tsx` の1箇所のみ。
- 既存の型エラー（`src/components/admin/RichTextEditor.tsx`／tiptap関連）は本件と無関係の別問題です。
