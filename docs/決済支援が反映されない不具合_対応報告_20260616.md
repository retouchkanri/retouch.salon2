# 決済支援なのに「会員種別 ―／支援数0／月額¥0」となる不具合 — 対応報告（2026-06-16）

## ご報告いただいた事象
- 小林真希 様（pikamemema@gmail.com）：Stripe では 2.5口の決済支援になっているが、管理画面で会員種別が空欄、支援数0頭/0口、月額合計¥0。
- 露崎真由美 様（buqn3639@gmail.com）：サブスクで 6,000円の半口支援×2件があるが、同じく会員種別「―」・支援数0・月額0。

## 原因
支援サブスクリプションは Stripe 上で「初回決済待ち（incomplete）」の状態で作成され、**会員が決済を完了した時に Stripe から届く Webhook 通知**を受けて、システム側の状態を「有効（active）」へ昇格させる設計です。

今回、この **Webhook がシステムに届いていなかった**ため、Stripe 上は決済完了（active）になっているにもかかわらず、データベースは `incomplete`（手続き中）のまま固着していました。

管理画面の「会員種別／支援数／月額合計」は **active の支援のみ**を集計するため、決済済みでも `incomplete` のままだと、会員種別が空欄・支援数0・月額¥0と表示されていました。

また、決済完了が反映されないまま会員が支援登録を繰り返したことで、未決済の重複サブスク（`incomplete_expired`）も発生していました。

## 対応内容

### 1. データの修復（実施済み）
Stripe を正として、`stripe_subscription_id` を持つ全契約（15件）の状態を実際の Stripe 状態に合わせて修正しました。**口数・月額は一切変更していません（状態のみ）。**

| 対象 | 結果 |
| --- | --- |
| 小林真希 様 | 3件 → 有効（SUPPORT会員・2.5口/3頭・月額¥30,000） |
| 露崎真由美 様 | 有効な半口×2件 → 有効（SUPPORT会員・1口/2頭・月額¥12,000）。未決済の重複9件は「停止（canceled）」へ整理 |
| その他1名 | 未決済の放置分1件を「停止」へ整理（会員状態に影響なし） |

修正前の状態は `backups/20260616_pre_reconcile_contracts.json` / `_support_subscriptions.json` にバックアップ済みです。

### 2. 再発防止（コード追加）
Webhook が万一届かなくても自己修復するように、Stripe の実状態を取り込む処理を追加しました。
- `src/lib/stripeReconcile.ts`：契約の状態を Stripe に合わせる（Webhook と同じ写像）。
- 管理ダッシュボード表示時に、`incomplete`/`past_due` の契約だけを対象に自動修復（軽量・表示は止めない）。
- 決済ページの「同期」ボタン（`/api/admin/payments/sync`）でも併せて状態を同期。
- 手動の一括修復スクリプト：`scripts/reconcile-subscription-status.mjs`（`--dry` でプレビュー、冪等）。

## 別途ご確認いただきたい点（請求金額の不一致）
小林真希 様の支援のうち1頭分（システム上は **0.5口=¥6,000**）が、Stripe では古い価格（**¥12,000**）で請求されています。実請求が月額¥6,000多い可能性があります。
- システム側の口数（2.5口=¥30,000）は会員の意図どおりです。
- Stripe 側の当該サブスク item の数量／価格の修正（および差額返金の要否）は、**金額に関わるためお客様のご判断**が必要です。対応方針をご指示ください。

## 全会員の横断点検（同型エラーの洗い出し）
「決済済みなのに会員種別が空欄」になる型の不具合が他にないか、Stripe の有効サブスク（1,239件）と DB を全件照合しました（`scripts/_audit-legacy-subs.mjs` 相当の調査）。

- 有効サブスクを持つ会員 **474名**のうち、**467名は正しく表示**（SUPPORT 153／基本会員 271／特別参加タグのみ 23 等）。
  - うち 23名（特別チーム 17・リタポ 6）は会員種別が「—」ですが、これは**仕様どおり**です（特別チーム・リタポは「会員種別」ではなく「特別参加」タグで表示されます）。タグは正しく表示されています。
- アプリ起因の `incomplete` 固着（小林・露崎と同型）は、上記修復で **残り0件**になりました。
- **完全に非表示だった会員 7名**（旧システムからの移行漏れ）を発見しました。これは今回の Webhook 不具合とは**別原因**（移行時に新システムの契約行が作られなかった）です。

## 推奨対応（インフラ設定の確認）
今回の根本原因は Webhook 未着です。Stripe ダッシュボードの Webhook エンドポイント設定（本番URL・購読イベント・署名シークレット `STRIPE_WEBHOOK_SECRET` の一致）をご確認ください。上記の自動修復はあくまで保険であり、Webhook が正しく届く状態が本来の正常系です。
